# Showcase research and design decisions

This is a short record of the public pages reviewed for the v0.1.0 GitHub presentation. The aim was to learn how visitors understand a product quickly, not to borrow anyone else's brand or media.

## GitHub's presentation rules

- A repository README is presented prominently to visitors; relative image and document links are portable across branches and forks. [GitHub README documentation](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)
- GitHub supports a `<picture>` element with `prefers-color-scheme` sources for light/dark images. [GitHub writing guide](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/quickstart-for-writing-on-github)
- Social preview is a **repository setting**, separate from README media; GitHub recommends 1280 × 640 and a file under 1 MB. [GitHub social preview guide](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/customizing-your-repositorys-social-media-preview)
- Topics are short, lower-case labels and are public metadata even for a private repository. [GitHub topics guide](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics)

## Open-source pages reviewed

| Project | Useful observation | AI Nexus decision |
| --- | --- | --- |
| [AppFlowy](https://github.com/AppFlowy-IO/AppFlowy) | A clear opening promise and an early installation path make a large app approachable. | Put a one-sentence position and quick-start link above the fold. |
| [AFFiNE](https://github.com/toeverything/AFFiNE) | Identity, product context, and destinations are visually grouped rather than mixed into a wall of setup notes. | Keep one brand opening, then product proof, then practical setup. |
| [Hoppscotch](https://github.com/hoppscotch/hoppscotch) | Strong brand framing coexists with direct paths to docs and code. | Use an original mark, restrained links, and a short technical section. |
| [Jan](https://github.com/janhq/jan) | A direct local-computing position and visible product media explain the experience quickly. | Show the real local interface and explain exactly what the demo data is. |
| [Raycast Extensions](https://github.com/raycast/extensions) | Developer contribution routes are easy to find, though its README is not a good model for a product screenshot. | Make contributing visible without making development notes the first screen. |
| [LocalSend](https://github.com/localsend/localsend) | Familiar product language and direct platform/install guidance reduce the first-run gap. | Name the supported platform and simplest connection path explicitly. |

None of these projects' images, copy, logos, icons, or code were reused. AI Nexus follows its own warm-neutral visual language and states beta limitations next to relevant claims.
